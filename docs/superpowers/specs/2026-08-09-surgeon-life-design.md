# 《外科醫師的一生》設計文件

日期:2026-08-09
狀態:已與作者確認核心設計,待實作

## 一、遊戲定位

輕量單頁網頁遊戲,人生重開模擬器式的「人生選擇器 RPG」。主角從**高中生**開始,走完(或走不完)一個外科醫師的一生。

**調性:寫實苦中帶淚。** 事件貼近真實,諷刺藏在細節裡,目標是讓圈外人也看懂外科的處境。

**諷刺主軸(四者皆有,分散在人生階段):**

1. 血汗健保與點值——開一台大刀的給付比修手機便宜
2. 醫療糾紛與防禦醫療——救人反被告,越來越不敢開刀
3. 過勞與人生失衡——青春全獻給開刀房
4. 五大皆空與人才流失——學弟妹都去醫美,留下來的人越來越苦

**最終訊息:沒有真正的完美結局。** 制度讓人無論怎麼選都有代價。

## 二、核心循環

遊戲以人生階段推進:

高中 → 醫學系 → PGY → 住院醫師 → 總醫師 → 主治(早期)→ 主治(中期)→ 主治(晚期)→ 結局(65 歲退休,或提前離場/倒下)

每個階段分兩步:

### ① 時間配置(玩家主動)

每階段有固定時間點數(代表這幾年的生命),分配到**五軸**:

| 投資項目 | 成長 | 誰在幫你打分數 |
|---|---|---|
| 臨床 | 手術技能 ↑ | 醫院考核你 |
| 教學 | 教學聲望 ↑ | 學生評鑑你 |
| 研究 | 論文點數 ↑ | 期刊審查你 |
| 家庭 | 家庭關係 ↑ | 家人等著你 |
| 個人 | 自我 ↑、健康回補 | **沒有人——包括你自己** |

高中/醫學系階段的五軸語意做對應調整(如臨床=課業/實習、研究=社團或實驗室、個人=興趣與生活)。

### ② 事件結算(命運回應)

配置完後播放該階段事件:固定劇情事件+隨機抽取事件。時間軸文字逐條浮現(人生重開模擬器的閱讀節奏),關鍵時刻跳出 2-3 個選項的抉擇。事件選項與結果受能力值影響(例:手術技能高 → 成功率高,但接到的轉診更難)。

## 三、屬性系統

**能力(時間投資的直接產出):**

- 手術技能
- 教學聲望
- 論文點數

**代價與狀態:**

- 家庭關係
- 自我(「個人」軸產出)
- 健康(「個人」軸回補)

**生存資源:**

- 存款——**與六項能力幾乎脫鉤**,主要由職級與制度事件決定

### 核心機制 1:能力與生存資源脫鉤

- 薪水由「職級 + 制度事件」決定。住院醫師薪水是死的;主治薪水看健保點值與醫院抽成——手術技能 90 分和 60 分,月薪差距極小。
- 手術技能高反而觸發:更難的轉診、更長的刀、更高的醫糾曝險。**能力的報酬是更多的工作。**
- 真正讓存款上升的路徑:減少練刀、兼醫美、或離開外科。遊戲不阻止,但「自我」與結局文字會誠實反映。

### 核心機制 2:升等只看論文

職級:住院醫師 → 主治 → 助理教授 → 副教授 → 教授。升等門檻只看**論文點數+教學時數**,手術技能不在公式裡。卡住的不是薪水(反正都差不多),是頭銜與排刀優先權。

### 核心機制 3:健康=壽命=遊戲長度

- 健康隨年齡自然下滑;臨床/研究投資過重會加速崩壞;「個人」投資是唯一回補來源。
- 健康見底 → 強制健康事件,可能直接死亡(過勞死結局)。**荒廢個人的玩家可能 45 歲倒在開刀房,連玩到結局的資格都沒有。**

### 核心機制 4:「自我」是結局的濾鏡

- 「自我」平常幾乎不影響遊戲進行——這正是它容易被歸零的原因:荒廢它短期毫無懲罰。
- 結局時,無論其他屬性多高,自我過低則所有結局蒙上同一層灰:
  > 「你到死的時候,始終不知道自己為什麼活得這麼累。」
- 自我夠高時,即使其他平庸,結局文字多一分和解感。

## 四、結局系統

遊戲終點:65 歲、提前離場(轉行/移民/醫美)、或健康歸零倒下。依最終屬性組合落入不同結局,例如:

- 手術技能滿、家庭歸零 →「手術室的傳說,家裡的陌生人」
- 中途轉醫美,存款滿、自我卻未必跟著滿 →「你的雷射打得又快又好」
- 論文滿貫升教授、手術平庸 →「你已經很久沒進開刀房了」
- 健康歸零 →「醫者不能自醫」
- 五軸平衡但全部平庸 → 最接近「好結局」,但遊戲會告訴你:你放棄了成為傳說的機會

每個結局附**人生結算單**:總刀數、救回人數、錯過的家庭晚餐、被告次數、沒人引用的論文數…——用數字讓玩家自己品味。

「自我」濾鏡疊加在所有結局之上(見核心機制 4)。

## 五、技術架構

方案 A:免建置純 Vanilla JS 靜態專案。

```
surgeon-life/
├── index.html
├── style.css
├── src/
│   ├── engine.js    # 純邏輯:屬性運算、階段推進、事件抽取、結局判定(不碰 DOM)
│   ├── events.js    # 事件資料(各階段固定+隨機事件)
│   ├── endings.js   # 結局判定表與結算單
│   └── ui.js        # DOM 渲染、時間配置介面、時間軸動畫
├── tests/           # Vitest
└── docs/
```

- ES module,瀏覽器直接開即玩,零建置。
- 部署:GitHub Pages。
- 手機優先的響應式版面(醫界同溫層以手機分享為主)。

## 六、測試策略

- **Unit test(Vitest,對 engine):** 屬性增減運算、時間配置驗證(五軸加總=預算)、健康衰退與死亡判定、升等判定、結局判定覆蓋所有分支。
- **資料完整性測試:** 每個事件/結局欄位齊全、數值合法、引用的屬性名稱存在。
- **Smoke test:** 以隨機策略自動玩完整場 N 次,確保任何配置都能走到某個結局、不會卡死或屬性爆界。

## 七、CI/CD

- ESLint + Prettier + pre-commit
- GitHub Actions:lint + test
- 依全域慣例於專案建立時設置。

## 八、明確不做(YAGNI)

- 不做存檔/雲端同步(一場 5-10 分鐘,重開即重玩)
- 不做音效/美術素材(純文字+CSS)
- 不做多主角/多科別(只有外科)
- 不做後端(純靜態)
